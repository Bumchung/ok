# 이스탄불과 두바이 가족여행 앱 재작성 프롬프트

이 문서는 두 앱을 다시 만들 때 생략하면 안 되는 요구사항과 사용자가 실제로 반려한 실패 사례를 한곳에 모은 기준 문서다. 이 기준을 통과하지 못하면 배포하지 않는다.

## 가족과 여행 조건

- 기간: 2027년 3월 20일 출발, 3월 21일 체크인, 3월 31일 체크아웃
- 인원: 성인 6명, 만 9세, 7세, 6세 아이 3명
- 출발: ICN팀과 LAX팀이 따로 출발해 현지 숙소에서 만남
- 숙소: 네 개의 분리 객실보다 4베드룸 한집, 레지던스, 빌라 선호
- 예산: 상한 없음. 최저가보다 수용 인원, 위치, 서비스, 취소와 실패 비용을 먼저 봄
- 리듬: 하루 한 곳, 오후 숙소 복귀, 관광일 다음 회복일, 긴 이동 최소화

## 사용자가 이미 반려한 결과

아래 50개 질문은 사용자가 이미 지적한 실패와 그 실패에서 파생된 재발 방지 질문이다. 하나라도 답을 못 하면 배포하지 않는다.

1. 왜 링크가 열리지 않는가?
2. 왜 디자인이 시드니 가족여행 앱보다 떨어지는가?
3. 왜 모바일에서 카드나 글자가 잘리는가?
4. 왜 사진이 없는 장소가 있는가?
5. 왜 장소와 관계없는 범용 사진을 반복해서 쓰는가?
6. 왜 말투가 AI가 쓴 기획서처럼 들리는가?
7. 왜 장소의 실제 장점과 반복되는 후기 불만이 반영되지 않았는가?
8. 왜 공식 정보와 여행자 후기와 기획자의 판단이 구분되지 않는가?
9. 왜 시드니판의 주변 검색, 실제 지도, 날짜별 사진, 질문 검색 기능이 빠졌는가?
10. 왜 Google Calendar 등록과 전체 일정 파일이 없는가?
11. 왜 10박 여행과 출발일부터 세는 12일 일정이 혼동되는가?
12. 왜 두바이가 이스탄불의 색만 바꾼 복제 앱처럼 보이는가?
13. 왜 두 도시의 장소 수와 식당 정보 밀도가 크게 다른가?
14. 왜 2027년 재고와 운항표를 확정된 사실처럼 보이게 하는가?
15. 왜 최종 배포 전에 50문항 자기감사와 공개 화면 검증을 하지 않았는가?
16. 왜 성인 6명과 만 9세, 7세, 6세 아이 3명이라는 조건이 화면에서 바로 보이지 않는가?
17. 왜 ICN팀과 LAX팀이 서로 다른 시간에 출발하고 도착한다는 사실을 일정에 반영하지 않았는가?
18. 왜 네 개의 객실을 따로 잡기보다 4베드룸 한집을 선호한다는 조건이 숙소 순위에 반영되지 않았는가?
19. 왜 숙소의 공식 정원, 침실 수, 욕실 수, 아이 동반 조건을 같은 기준으로 비교하지 않았는가?
20. 왜 예산 제한이 없다는 말을 비싼 곳을 고르라는 뜻으로 오해하고 이동과 실패 비용을 무시했는가?
21. 왜 매일 부모가 기대할 것, 아이가 기다릴 것, 함께 남길 장면, 오후 회복을 실제 하루 리듬으로 보여 주지 않았는가?
22. 왜 하루에 꼭 볼 곳을 하나로 정하지 않고 여러 곳을 억지로 묶었는가?
23. 왜 체력이 많이 드는 날 다음에 쉬는 날을 두지 않았는가?
24. 왜 도착일에 관광이나 합류 행사를 넣었는가?
25. 왜 카파도키아, 아부다비, 사막처럼 왕복 이동이 긴 곳을 대표 코스라는 이유만으로 넣었는가?
26. 왜 2027년 일별 날씨를 아직 알 수 없는데 예보처럼 보이게 했는가?
27. 왜 휴관일, 기도 시간, 강풍, 수영장과 워터파크 제한을 날짜에 맞춰 확인하지 않았는가?
28. 왜 비 오면과 힘들면 대안을 모든 날짜에 넣지 않았는가?
29. 왜 아홉 명이 한 테이블에서 먹는 식사를 매일 어떻게 해결할지 적지 않았는가?
30. 왜 식당의 어린이 입장 나이, 9인 예약, 어린이 의자, 알레르기 확인을 빼먹었는가?
31. 왜 리뷰가 좋은 곳도 우리 가족과 맞지 않으면 제외할 수 있다는 판단을 보여 주지 않았는가?
32. 왜 후기의 칭찬만 가져오고 긴 줄, 높은 가격, 계단, 혼잡 같은 반복 불만은 숨겼는가?
33. 왜 후기 출처와 확인일이 없어서 언제 본 정보인지 알 수 없는가?
34. 왜 사진 출처가 없거나 장소 이름과 실제 사진이 다른가?
35. 왜 사진이 실패했을 때 범용 사진을 보여 주면서 실제 장소 사진이라고 표시하는가?
36. 왜 현재 위치 권한을 거절하면 주변 추천 전체가 망가지는가?
37. 왜 지도에 실제 타일, 장소 핀, 확대와 축소, Google Maps 길찾기가 없는가?
38. 왜 장소 검색이 이름만 찾고 후기 불만, 아이 조건, 빼야 할 상황은 찾지 못하는가?
39. 왜 질문 기능이 외부 AI 서버가 없으면 아무 답도 하지 못하는가?
40. 왜 개인 Google 계정 권한이나 비밀키 없이 날짜별 일정을 Calendar에 추가할 수 없게 만들었는가?
41. 왜 전체 일정을 한 번에 가져가는 ICS에 12개 날짜가 모두 들어 있지 않은가?
42. 왜 장소 목록을 CSV와 KML로 내보낼 수 없는가?
43. 왜 모바일 하단 이동, 터치 크기, 안전 영역을 확인하지 않았는가?
44. 왜 키보드 포커스, 본문 건너뛰기, 모션 줄이기, 이미지 대체문구를 확인하지 않았는가?
45. 왜 사진 하나나 외부 API 하나가 실패하면 페이지 전체가 깨지는가?
46. 왜 이스탄불 앱과 두바이 앱이 각자 폴더만으로 실행되지 않는가?
47. 왜 2027년 항공편, 객실 10박 연속 재고, 침대 배치를 예약 완료처럼 보이게 하는가?
48. 왜 공개 배포본에서 사진 fallback 수와 깨진 이미지 수를 세지 않았는가?
49. 왜 시드니판을 기준으로 한 시각 판정이 90점 미만인데도 최종본이라고 했는가?
50. 왜 공개 주소의 HTML, CSS, 자바스크립트, 데이터, 사진이 모두 HTTP 200인지 직접 확인하지 않았는가?

## 시드니판에서 반드시 가져올 기능

- 현재 위치를 켜면 가까운 장소부터 정렬되는 주변 추천
- 장소 카드의 사진, 운영 정보, 예약 난이도, 가족 적합성, 공식 링크, 지도 링크
- 여행자 후기에서 반복되는 장점과 불편을 분리해 보여 주는 리뷰 요약
- 날짜별 대표 사진, 오늘 이곳을 넣은 이유, 부모의 기대, 아이의 기대, 함께 남길 장면, 오후 회복, 이동 방식, 체력, 비 오는 날 대안
- 확대, 축소, 권역 필터, 현재 위치, 장소 상세가 있는 실제 지도 타일
- 화면 어디서든 열 수 있는 여행 질문 검색
- Google Calendar에 날짜별 일정을 추가하는 링크
- 전체 일정을 한 번에 가져가는 ICS 파일
- CSV와 KML 내보내기
- 모바일 빠른 이동, 여행 상태, 다음 행동, 접근성, 이미지 실패 폴백

## 문체

- 세 가족 여행을 먼저 꼼꼼히 준비한 사람이 가족 단톡방에서 설명하는 해요체
- 결론부터 말하고, 바로 다음 문장에서 실제 이유와 손해를 설명
- `운영 안정성`, `완결성`, `효용`, `기본값`, `저강도`, `의사결정` 같은 추상 용어를 피함
- `비 오면`, `힘들면`, `아홉 명 식사`, `예약 전에 물어볼 것`처럼 사람이 현장에서 쓰는 표현 사용
- 근거 없는 96점 같은 가짜 정밀도는 제거하고 비교 기준을 글로 공개

## 장소 데이터 계약

모든 장소는 다음 정보를 가져야 한다.

- 장소를 정확히 보여 주는 대표 사진과 다른 호스트의 폴백 사진
- 우리 가족에게 좋은 이유
- 여행자 후기에서 반복되는 장점 2개 이상
- 여행자 후기에서 반복되는 불편 1개 이상
- 아이 셋과 갈 때의 구체적 사용법
- 예상 체류시간, 체력, 비 오는 날 적합성, 예약 필요도
- 공식 정보 출처와 후기 출처, 확인일
- Google Maps 길찾기

## 완료 조건

- 두 앱이 서로의 파일 없이 독립 실행
- 사진 URL 전수 확인, 화면상 빈 사진 0개
- 자동 테스트, 문법 검사, 데이터 내보내기 통과
- 데스크톱과 실제 430px 모바일 전 구간 캡처
- 시각 판정 90점 이상
- 50문항 자기감사 통과
- GitHub Pages의 HTML, CSS, 자바스크립트, 데이터 파일이 모두 HTTP 200
- 2027년 항공편, 객실 재고, 침대 배치는 미확정 상태를 명확히 표시
